1. 함수에서 값을 return 하지 않고 self._ = 형식으로 넣어버릴 때의 문제점
테스트 할 때 반환 되는 구조 일 때 검증이 쉽다
만약에 코드가 복잡해 져서 함수가 불러지지 않고 인스턴스 변수를 요청했을 때 오류가 발생
왜냐하면 아직 값이 만들어지지도 않았는데 값을 불러오는 오류를 범할 수 있다

2.MAC 연산과 AI에서 중요한 이유
먼저 MAC연산은 동시에 계산 하는 것
cpu는 일열로 직열 처리 - 범용성이 높은 작업에서 유리
gpu는 병열로 동시에 계산을 처리 - AI에서는 대량의 단순한 계산이 많기에 더 효율적

3.이미지의 유사도를 측정하는 다양한 방법
과제에서 나온 내용은 같은 위치의 서로 다른 두 점을 곱해서 유사도를 측정하지만
이때 생길 수 있는 문제는 이미지가 조금이라고 이동하면 같은 이미지라고 유사도가 매우 낮게 나올 수 있다는 의문이 생김
따라서 실제에서는 이와 같은 방법을 어떻게 해결하는지 또한 더 좋은 방법이 있는지를 검색해봄
그 결과 실제에서는 순차적으로 백터를 탐색하는 합성곱 방법처럼 다양한 것 들이 존재함

4. 정규화하는 이유
의미가 같은 라벨을 올바르게 같은 것으로 판단할 수 있습니다.
데이터 입력 방식이 달라도 프로그램이 안정적으로 동작함

5. 파일 오픈할 때 
예전에는 파일을 오픈 할 떄 
f = open(파일이름, 'r', encoding = 'utf-8')
f.close()
를 사용했지만 이와 같은 방법은 닫아주지 않으면 오류가 발생함 그래서 새롭게 나온 것이
with open(파일이름, 'r', encoding = 'utf-8') as f의 방식임
이 방식은 내가 블록을 벗어나는 순간 자동으로 close()가 불려짐

6. 허용 오차란
실제 컴퓨터가 10진수를 2진수로 바꾸는 과정에서 생기는 미세한 차이 때문에 값을 그냥 비교하면 결과가 다르게 나올 수 있다.
따라서 8.99999 == 9.0 이랑 같은 수 라고 생각 하기 때문에 코드에서 기준을 두어 따로 처리한다.
